Inference for the agentic era

Your agent pays twice for the same conversation.

The problem

Agents don’t work like chat. Inference still assumes they do.

A chat message is one model call and it’s finished. An agent task is dozens of calls with long gaps in between — searching, running code, waiting on a tool, waiting on a person. Every one of those calls resends the entire conversation so far.

While the agent is paused, the server has no idea it’s coming back. So it clears the model’s working memory of that conversation to make room for someone else. When the agent returns, everything gets read from scratch.

The cost of a miss grows with the conversation. Lose it on turn three and you re-read a few thousand tokens. Lose it on turn thirty and you re-read everything. So the waste lands exactly where it hurts most, on the longest and most valuable tasks.

How we solve it

Four things a serving layer built for chat will not do.

None of this is exotic. It is scheduling and routing, done for a workload nobody designed for.

Know a pause is coming

When an agent calls a tool, that is a signal. The gap is starting now and it will last minutes. We treat that as the moment to move the conversation's memory somewhere cheaper, deliberately, instead of waiting for the server to run out of room and guess.

Send it back where it came from

When the agent returns, its memory sits on one specific machine. Standard routing sends the request to whichever machine is least busy, which is usually the wrong one. We route on where the conversation already lives, then on load.

Keep paused work, drop finished work

A conversation that ended and one that is thinking look identical to most systems, so they clear whichever is older. That is backwards. A finished task will never return. A paused one returns in ninety seconds.

Move it or rebuild it, whichever is cheaper

Sometimes the original machine is busy and the conversation has to go elsewhere. Moving its memory across the network costs something. Rebuilding it from scratch costs something else. Which is cheaper depends on how long the conversation is. We work it out per request instead of always rebuilding.

Why India

Three costs that only apply here.

Paid in rupees

Inference is billed in dollars by companies abroad, and Indian buyers pay 18% import tax on top. That is a cost that grows with every user you add, in a currency you don't earn.

Stays in India

For most companies this doesn't matter. For banks, insurers and hospitals it decides the vendor. If your data has to stay inside the country, running the model here is not a preference.

Indian languages cost more

Models chop Indian languages into four to five times more pieces than English, and Malayalam into far more than that. You are billed per piece. Choosing the right model for the language is a cost decision nobody abroad has a reason to make for you.

We're building, not selling.

Two founders in Bangalore. We have a gateway running — authentication, routing, streaming, usage metering per request — serving open models end to end. It is early and rough.

What we don’t have yet is the measurement. That comes next: how much Indian agent workloads actually lose across the gaps, benchmarked on rented Indian GPUs, published with the method so anyone can check it or disagree with it.
